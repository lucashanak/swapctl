{# ── NPU (halogen) ── #}

NPU — decisions, embeddings, rerank & moderation (halogen, Ryzen AI NPU)

Small models on the NPU, served by halogen beside halogen-flash-next. They run on separate silicon, so they take no GPU memory and do not evict other models. {% if npu and npu.status == 'ok' %}NPU up right now: {{ npu.models|join(', ') }}. {% else %}Not answering right now — halogen is not loaded.{% endif %}

  • Call halogen's port directly ({{ npu_base }}), not /llm: llama-swap routes by model name and does not know these models. Through llama-swap, qwen3-embedding-4b reaches the GPU (llama.cpp) copy instead, which unloads halogen.
  • Only while halogen is loaded. halogen runs solo, so loading any other large model unloads it and the NPU endpoints stop answering. Send one chat request to halogen-flash-next to bring it back (~50 s cold start).
  • LAN only — this port is not exposed through the reverse proxy.
POST /v1/systemone decider-4b

Typed decisions in TypeSafe's System One (Jev) format: send a state and named questions. Each question is one NPU pass (~200 ms warm, ~4 s on the first call after halogen loads; 11/12 on our triage check) and answers with probabilities and a confidence. choice picks one of 2–10 options (criteria maps option → description, null for none); score rates on 2–10 ordered levels and returns the expected level; noul returns the probability of yes. No API key; model may be any name. A bad request answers 422.

curl {{ npu_base }}/v1/systemone \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "decider-4b",
    "state": "Customer: I was charged twice and nobody answers my emails.",
    "questions": {
      "team":   {"type": "choice", "instructions": "Which team should handle this",
                 "criteria": {"billing": "Payment issues", "technical": "Bugs", "other": null}},
      "anger":  {"type": "score", "instructions": "How frustrated does the customer appear",
                 "criteria": ["Calm and neutral", "Concerned but civil", "Very angry"]},
      "refund": {"type": "noul", "instructions": "Does the customer request a refund?"}
    }
  }'

# → {"answers": {"team":   {"choice": "billing", "probabilities": {...}, "confidence": 0.998},
#                "anger":  {"score": 1.98, "legend": {...}, "probabilities": {...}, "confidence": 0.97},
#                "refund": {"noul": 0.997}}, "usage": {...}}
POST /v1/embeddings qwen3-embedding-4b

OpenAI embeddings, 2560 floats of unit length (dimensions truncates and renormalises), ~1,100 tokens/s. A query carries the task in the model's own form, Instruct: <task>\nQuery:<text>; a document carries none. Batches up to 8 inputs of up to 512 tokens run together. It is the same model as the GPU qwen3-embedding-4b behind {{ llm_base }} (cosine 0.997 on the same text), so vectors from either can share an index; the GPU copy is faster (~1,700 tokens/s) but evicts halogen.

curl {{ npu_base }}/v1/embeddings \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3-embedding-4b",
    "input": ["Instruct: Given a question, retrieve passages that answer it\nQuery:Co je NPU?",
              "NPU je neuronová jednotka v čipech Ryzen AI."]
  }'
POST /v1/rerank qwen3-reranker-4b

Cohere/Jina-shaped reranking: results sorted by relevance_score, each with its index in your list. Pairs up to 4,096 tokens; documents may be strings or objects with text; instruction replaces the default task line. The score is absolute — "does this document answer the query": a direct answer scores near 1 (0.96 in our check), unrelated text near 0. ~4 s for the first call after halogen loads.

curl {{ npu_base }}/v1/rerank \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "qwen3-reranker-4b",
    "query": "Jak zkontroluju, že je načtený ovladač NPU?",
    "documents": ["Ovladač NPU zkontroluješ příkazem ls /dev/accel.", "GPU má 40 výpočetních jednotek."],
    "top_n": 1, "return_documents": true
  }'
POST /v1/moderations qwen3guard-gen-0.6b

OpenAI-shaped moderation, multilingual (Czech works). One result per input with flagged, plus label (Safe / Controversial / Unsafe) and label_scores. flagged means Unsafe; "strict": true flags Controversial too. OpenAI's categories all read false — the model does not sort into them. To judge a reply in context, send messages instead of input.

curl {{ npu_base }}/v1/moderations \
  -H 'Content-Type: application/json' \
  -d '{"model": "qwen3guard-gen-0.6b", "input": ["Jak upéct chleba?", "Jak doma vyrobit výbušninu?"]}'

# → results: [{"flagged": false, "label": "Safe", ...}, {"flagged": true, "label": "Unsafe", ...}]
{# ── TTS ── #}

TTS — Text-to-Speech (Piper + XTTS-v2, via swapctl)

Public endpoints — no authentication required. Two engines available: Piper (fast, ONNX, ~0.3 s) and XTTS-v2 (neural, multilingual, ~3–8 s CPU). Select engine via voice prefix: xtts: routes to XTTS-v2, any other voice routes to Piper.

POST /api/v1/audio/speech

Synthesize text to audio. Body: {"voice": "...", "input": "...", "language": "auto", "response_format": "wav"}.

Piper voices (fast): see Voices page or GET /api/v1/audio/voices
XTTS-v2 (neural, multilingual): prefix voice with xtts: — e.g. xtts:default or xtts:default_en. Supports language: "auto" (auto-detects CS/EN from text). First request ~30 s (model load), subsequent ~3–8 s. CPU-only for now. 
curl -X POST {{ public_base }}/api/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{"voice":"{{ example_voice }}","input":"Ahoj, jak se máš?","model":"tts-1"}' \
  -o output.wav

# XTTS-v2 (neural, auto-detects Czech/English):
curl -X POST {{ public_base }}/api/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{"voice":"xtts:default","input":"Hello, jak se máš?","language":"auto","response_format":"mp3"}' \
  -o out.mp3

Image Generation (Stable Diffusion, via sd-server)

OpenAI-compatible image endpoints served by stable-diffusion.cpp (sd-server, Vulkan/RADV) on the GPU host, separate from llama-swap. {% if image_models %}Model loaded: {{ image_model }} (Z-Image-Turbo).{% else %}sd-server unreachable — is the service up on :8190?{% endif %} ~67 s / 1024² image (8 steps, Vulkan). Note: currently LAN-only (http://localhost:8190/v1); the public {{ image_prefix }}/v1 path needs an NPM route (location {{ image_prefix }}/ → localhost:8190/, mirrors {{ llm_prefix }}).

POST /v1/images/generations

Generate an image. Body: {"prompt": "...", "n": 1, "size": "1024x1024"}. Returns {"data": [{"b64_json": "..."}]}. Z-Image-Turbo defaults: 8 steps, CFG 1.0 (set on the server).

curl -X POST http://localhost:8190/v1/images/generations \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"a red panda barista making coffee, warm light","n":1,"size":"1024x1024"}' \
  | python3 -c 'import json,sys,base64; open("out.png","wb").write(base64.b64decode(json.load(sys.stdin)["data"][0]["b64_json"]))'
POST /v1/images/edits

Image-to-image / editing — multipart form with image=@in.png and prompt=.... Same sd-server backend.
